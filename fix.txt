

### 3\. Fix the Data Transfer Bottleneck (Most Impactful Refactor)

This is your **biggest hidden bottleneck**.

Your current logic is:
`Client (GPU)` -\> `.cpu()` -\> `.numpy()` -\> `UAV (CPU)` -\> `Numpy list` -\> `Trainer (CPU)` -\> `Tensor` -\> `state_dict` -\> `Satellite (CPU)`

That `.cpu().numpy()` conversion is slow and blocks the main thread. You should **pass `state_dict` objects around directly** (which are just CPU-based dictionaries). This requires a refactor but is the "correct" PyTorch way.

#### Step 3.1: Change `client.py`

Have `local_train` return the `state_dict` directly. This avoids `get_model_parameters`.


#### Step 3.2: Change `uav.py`

Modify `aggregate_updates` to take and return `state_dict`s. You can borrow the logic from your `satellite.py` file.

```python
# In uav.py

# ... (imports) ...

class UAV:
    # ... (__init__) ...

    def aggregate_updates(self, client_updates):
        """Aggregates model updates from selected clients using Federated Averaging (FedAvg).

        Args:
            client_updates (list of tuples): Each tuple contains (client_state_dict, num_samples).

        Returns:
            OrderedDict: The aggregated model state_dict.
        """
        if not client_updates:
            return self.model.state_dict() # Return current state

        total_samples = sum(num_samples for _, num_samples in client_updates)
        
        # Get the keys from the first model
        state_dicts = [sd for sd, _ in client_updates]
        keys = state_dicts[0].keys()
        
        avg_state_dict = OrderedDict()

        for key in keys:
            # Sum weighted tensors for the current key
            summed_tensor = torch.zeros_like(state_dicts[0][key]) # Init on CPU
            for sd, num_samples in client_updates:
                weight = num_samples / total_samples
                summed_tensor += sd[key] * weight
            
            avg_state_dict[key] = summed_tensor
            
        return avg_state_dict
```
